Discord replaced 177 database servers with 72. And the app got faster. Here's the story of how, and it's not what you'd expect.

Discord stores trillions of messages. For years, they lived in Cassandra, a database made to spread huge amounts of data across many servers. Messages are grouped by channel and by time, so reading a chat is quick.

But as Discord grew, three problems showed up.

The first was hot partitions. Some channels are enormous. When thousands of people read the same busy channel at once, the servers holding that data get hammered. And since reads need several servers to agree, one overloaded server slows down everyone who touches it.

The second was garbage collection. Cassandra runs on the Java virtual machine, which occasionally stops everything to clean up memory. Those pauses showed up as random latency spikes.

The third was maintenance. Data files pile up, and need compacting. At times, engineers had to take servers out of rotation one by one, just so they could catch up. They jokingly called it the gossip dance.

So Discord made two changes.

First, they moved to ScyllaDB. It's compatible with Cassandra's data model, but it's written in C++, which has no garbage collector, and it splits its work so each CPU core runs independently.

Second, and just as important, they put a new layer in front, written in Rust. If a thousand users ask for the same messages at the same moment, it sends one query to the database and shares the answer. And requests for the same channel are always routed to the same service, so the sharing works well.

The results: reading history went from a 99th-percentile latency of 40 to 125 milliseconds, down to about 15. Writes went from 5 to 70, down to about 5. And 177 nodes became 72.

Moving the data took nine days, at about 3.2 million messages per second.

Sometimes the answer isn't more servers. It's removing the pauses.
