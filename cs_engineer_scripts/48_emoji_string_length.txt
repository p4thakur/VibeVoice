Ask JavaScript how long the family emoji is, one single picture of a family, and it answers 11. Not 1. Eleven. And that answer, as absurd as it looks, is correct, and the reason why is something every engineer who touches text eventually gets burned by. "The length of a string" is one of the most deceptive questions in programming.

Start with how text is actually stored. A computer doesn't store letters, it stores numbers, and the map from characters to numbers is called Unicode. Every character, every letter, every symbol, every emoji, is assigned a number called a code point. The letter A is code point 65. The grinning face emoji is code point 128,512. So far it sounds like one character, one number. The trouble is in how those numbers get packed into memory, and that happens in layers.

Here's the first layer. Languages like JavaScript store text in a format called UTF-16, which packs each code point into chunks of 16 bits, called code units. A 16-bit chunk can only hold numbers up to 65,535. Letters and common symbols fit in one chunk. But the grinning emoji is code point 128,512, far bigger than 65,535. So it can't fit in one 16-bit chunk. Unicode handles this with a trick called a surrogate pair: big code points are split across two chunks. So that one emoji is two code units. And JavaScript's length counts code units. One emoji, length two. That's the first surprise.

Now the family emoji, which is where it gets wild. A family picture isn't a single character at all. It's built by gluing together separate people emoji with an invisible connector called a zero-width joiner. So the family of four is really: man, joiner, woman, joiner, girl, joiner, boy. That's seven code points. And each of the four people emoji is a big code point, so each is a surrogate pair, two code units. Four people at two units each is eight, plus three joiners at one unit each is three, totaling eleven code units. So JavaScript, counting code units, says the length is 11, for one picture you'd call a single character. The computer is counting the raw building blocks; you're seeing the assembled result.

So we have at least three different, all legitimate, answers to "how long is this." Eleven code units, the raw storage chunks. Seven code points, the Unicode numbers. And one grapheme, which is the word for what a human actually perceives as a single character, the thing you'd delete with one press of backspace. Each layer is a valid count for a different purpose, and using the wrong one is where bugs live.

And these are real bugs. Say you limit usernames to 20 characters by checking the code-unit length, a user types 20 emoji, and your check sees 40 or more, rejecting valid input. Or you truncate a message to fit a database column by chopping at a code-unit count, and your cut lands in the middle of a surrogate pair or between a person and their joiner, splitting one emoji into broken fragments, the little replacement boxes you've seen in corrupted text. Reverse a string naively to reverse its code units, and every multi-unit emoji shatters. Flags, which are built from pairs of letter-like regional symbols, scramble into different flags or garbage.

One family, eleven units, seven code points, one grapheme. The string didn't lie to you. It answered a more precise question than the one you thought you were asking.
