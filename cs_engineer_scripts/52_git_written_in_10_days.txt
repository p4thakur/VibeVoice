The tool that nearly every software developer on Earth uses to manage their code, Git, was created in about ten days in 2005 by Linus Torvalds, in a burst of frustration, as a side project to the side project. Unlike JavaScript, also built in roughly ten days, Git's hasty birth produced something elegant and enduring, because of one difference that's the whole lesson: Git started from a clear, correct mental model and the right data structure, and raw speed built on a solid idea gives you something very different from speed spent papering over a shaky one.

Start with why it had to be built at all, under pressure. Linux, the operating system kernel Torvalds created, was developed by thousands of contributors worldwide, and coordinating all their changes needs a version control system, software that tracks every change to the code, who made it, and lets people work in parallel and merge their work. The Linux project had been using a commercial system called BitKeeper under a free arrangement, but in 2005 that arrangement broke down and the free access was revoked. Suddenly the world's most important open-source project had no good tool to manage its code, and the existing alternatives were, in Torvalds's view, too slow and poorly designed for a project of Linux's scale and distributed nature. So he decided to write his own, fast, and within about ten days had something working, and the Linux kernel was soon managing itself with it.

Now the crucial difference from a rushed prototype that ages badly: Git was built around a clear and correct idea of what version control should be, not bolted together feature by feature. Torvalds had strong opinions, forged by years of pain, about what he needed: it had to be distributed, so every developer has the full history on their own machine and can work offline, with no central server as a bottleneck or single point of failure. It had to be fast, so that thousands of contributors and a huge history didn't bog it down. And above all it had to guarantee integrity, so that the code's history could never be silently corrupted or tampered with. Those requirements shaped a clean underlying design, rather than being patched on afterward.

And here's the elegant core, which connects to ideas we've built up. Git stores everything using content-addressing: every piece of content, every version of a file, every directory structure, every commit, is identified by a hash of its contents, the same fingerprinting idea behind Dropbox's deduplication and Merkle trees. A file's identity is the hash of what's in it. A directory is identified by a hash built from the hashes of the files it contains. And a commit, a saved snapshot of the whole project, is identified by a hash built from the directory it captures plus the commit before it. So each commit's identifier depends on its entire history, exactly like a Merkle tree or a blockchain. This gives integrity for free: if even a single byte of any file, anywhere in the history, were changed, its hash would change, which would change its directory's hash, which would change every commit built on top, so the tampering is instantly detectable. The history is cryptographically chained. It also makes Git fast and space-efficient, because identical content, the same file version appearing in many places, is stored once and referenced by its hash, deduplication, again. The whole powerful system rests on that one simple, correct idea: name everything by a fingerprint of its content, and link those fingerprints into a chain.

That's why two tools built in about ten days aged so differently. JavaScript's rush produced quirks layered on an unclear foundation, frozen in forever. Git's rush produced a tool whose surface commands people do find confusing, but whose underlying model is so clean and sound that it won almost completely and has needed no fundamental rework. Speed wasn't the deciding factor. The presence or absence of a clear, correct model underneath was.

The world's version control system was a ten-day side project born of frustration, and it endured because it started from a clear idea and the right structure, every version named by a fingerprint of its contents, chained so nothing can be secretly changed. Speed on a solid foundation builds something permanent. Speed without one just freezes the mess.
