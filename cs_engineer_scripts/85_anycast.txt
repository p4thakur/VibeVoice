The same internet address, the very same numeric IP, exists in hundreds of cities around the world at the same time. You type it, and without doing anything, you reach whichever copy is physically nearest to you. Someone in Delhi and someone in Dallas type the identical address and land on two different machines thousands of miles apart. This is anycast, and it's one of the quiet mechanisms making the internet fast, resilient, and resistant to attack, all at once.

Start with how addresses normally work. An IP address usually belongs to one specific machine in one specific place. A packet sent to that address gets routed, hop by hop, across the internet to that one destination. This one-address-one-machine model is called unicast, and it's the default mental picture everyone has.

Anycast deliberately breaks that model. It announces the same IP address from many locations at once. To understand how that's even possible, you need to know how the internet decides where to send packets. The internet is a mesh of networks that constantly tell each other, "to reach this range of addresses, send traffic through me," using a protocol called BGP, the same announcement system behind the famous Pakistan-YouTube incident, where a bad announcement hijacked YouTube's traffic worldwide. Normally one place announces a given address. With anycast, a company announces the same address from its data centers in Mumbai, Frankfurt, Virginia, São Paulo, and dozens more. Every router across the internet hears multiple announcements for that one address, and routers already have a rule for this: pick the shortest, best path. So each router naturally forwards packets for that address to the nearest announcing location. Your packets flow to the closest copy, automatically, because the internet's normal routing already prefers the nearest source of an address. You don't configure anything. The routing fabric does it for you.

The benefits stack up, and each is worth seeing. First, speed and proximity. By placing the same address in many locations, every user is served from one near them, which means shorter physical distance, fewer network hops, and lower latency. This is a backbone of how content delivery networks and public DNS resolvers work, Cloudflare's resolver at 1.1.1.1 and Google's at 8.8.8.8 are single addresses answered by machines on every continent. It's also how the internet's 13 DNS root server addresses become over a thousand physical machines, as we'll see with DNS, anycast is the trick that turns a handful of addresses into a global fleet.

Second, resilience. If one location goes down, its announcement simply disappears from the routing tables, and routers automatically start sending that address's traffic to the next-nearest location instead. Users barely notice, their packets just quietly reroute to another copy. There's no failover to configure, the loss of a site is handled by the same routing mechanism that chose it in the first place.

Third, and elegantly, defense against attacks. In a denial-of-service attack, a flood of malicious traffic is aimed at an address to overwhelm it. But with anycast, that flood doesn't converge on one machine, because each attacking source's traffic also goes to its own nearest location. So the attack gets split across all the locations announcing the address, each one absorbing only the share of attackers nearest to it. A flood that would drown a single server is divided among hundreds, which is a major reason large infrastructure providers can withstand enormous attacks.

Nothing is free, and anycast's limitation comes from the very thing that makes it work. "Nearest" is decided by internet routing, which can change. For a quick exchange, like a single DNS question and answer, that's fine, the whole thing completes in one round trip to one location. But for a long-lived connection, if the best route shifts midway, your packets could suddenly start arriving at a different location that knows nothing about your ongoing conversation, breaking it. So anycast is ideal for short, self-contained request-response exchanges, and for longer sessions it's used carefully, often as an entry point that then hands off to a stable address, or paired with techniques that keep a connection pinned to one location.

One address, a hundred doors, scattered across the planet, and the internet quietly opens the closest one for every person who knocks. Same number, nearest machine, chosen for you by the way the network already works.
