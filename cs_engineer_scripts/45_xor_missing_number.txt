I'll give you a bag with every number from 0 to a billion in it, except one is missing, all jumbled up. Find the missing number. The obvious ways either use a lot of memory or risk breaking on huge numbers. There's a way that uses almost no memory, never overflows, and reads each number exactly once, using a single operation most people never think about: XOR. And understanding why it works teaches you something deep about reversible operations.

First, the obvious approaches and their costs. You could sort the numbers and look for the gap, but sorting a billion numbers is slow and moves a lot of data. You could make a checklist of a billion boxes and tick each number off, but that's a lot of memory. The cleverer classic is to add them all up: the sum of 0 to n has a known formula, n times n plus 1, over 2, so subtract the actual sum from the expected sum and you get the missing number. That's fast and uses little memory, but with a billion numbers that sum is astronomically large and can overflow a normal integer, silently giving a wrong answer, the very bug we've seen wreck rockets.

Now the XOR method. XOR, exclusive or, is a bitwise operation on two numbers: for each bit position, the result is 1 if the two bits differ, and 0 if they're the same. It has three magical properties. First, any number XORed with itself is 0, because every bit matches. Second, any number XORed with 0 is itself, unchanged. Third, order doesn't matter at all, you can XOR a pile of numbers together in any sequence and get the same answer.

Put those together. Take every number from 0 to n and XOR them all into a running total. Then take every number actually in the bag and XOR them into that same total. Now think about what survives. Every number that appears in both lists, which is all of them except the missing one, appears twice in the combined pile, once from the full range and once from the bag. And a number XORed with itself cancels to 0. So every present number cancels itself out. The only number that appears an odd number of times, just once, is the missing one, because it's in the full range but not in the bag. It has nothing to cancel against. So after all the canceling, the total is exactly the missing number.

That's the whole algorithm. One pass through the data, a single running number as your only memory, and no addition, so no sum to grow too large and overflow. It works on a billion numbers or a trillion, in a few bytes of memory.

The deep idea is that XOR is its own undo. Most operations lose information, once you add 3 plus 5 to get 8, you can't recover the 3 and the 5. XOR doesn't lose that way: applying the same value twice returns you to where you started. That reversibility is why it shows up all over real systems. RAID disk arrays use it for redundancy: XOR several drives together onto a parity drive, and if one drive dies, you XOR the survivors with the parity to reconstruct the lost data exactly, the same canceling trick. It's used in simple encryption, in graphics, and in the classic puzzle of swapping two variables without a temporary one. Wherever you need to combine things so they can be perfectly separated again, XOR is the tool.

A billion numbers, one missing, found in one pass and a few bytes, with no risk of overflow. The point isn't the puzzle. It's that choosing an operation that cancels itself can turn a problem that needs a lot of memory into one that needs almost none.
